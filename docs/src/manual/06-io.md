# 6. Input and output

```julia
using BioNExt

kg = KnowledgeGraph()
add!(kg,
    Taxon(id = "NCBITaxon:9606", name = "Homo sapiens"),
    Gene(id = "HGNC:6973", name = "MDM2", organism = "NCBITaxon:9606"),
    Protein(id = "UniProt:P04637", name = "p53", synonyms = ["TP53", "LFS1"],
            cellular_location = [:Nucleus], organism = "NCBITaxon:9606"),
    Protein(id = "UniProt:Q00987", name = "MDM2", organism = "NCBITaxon:9606"),
    Interaction(id = "e1", type = :Binding, left = ["UniProt:Q00987"], right = ["UniProt:P04637"],
                confidence = 0.98),
    Influence(id = "e2", type = :RegulateExpression, left = ["UniProt:P04637"], right = ["HGNC:6973"]),
    Influence(id = "e3", type = :Inhibition, left = ["UniProt:Q00987"], right = ["e2"], weight = 0.8),
    PathwayModule(id = "PW", name = "p53–MDM2 loop", components = ["e1", "e2", "e3"]),
)
```

## `load` and `save`

Three functions cover every format. They pick the format from the file extension:

```julia
save("loop.ttl", kg)                    # write
kg2 = load("loop.ttl")                  # read into a new graph
load!(kg2, "loop.ttl"; replace = true)  # read into an existing graph
```

Pass `format` when the extension is missing or misleading:

```julia
save("loop.data", kg; format = :jsonld)
load("loop.data"; format = :jsonld) |> length       # -> 8
```

Any other keyword arguments go to the format's own reader or writer. Those options are
described in the sections below. `formats()` lists what is available:

```julia
[(f.format, f.read, f.write) for f in formats()][1:3]
# -> [(:csv, true, true), (:dot, false, true), (:graphml, false, true)]
```

| Format | `format =` | Extensions | Read | Write | Best for |
|---|---|---|:-:|:-:|---|
| Turtle | `:turtle` | `.ttl` `.turtle` | ✓ | ✓ | publishing, reading by eye, version control |
| N-Triples | `:ntriples` | `.nt` | ✓ | ✓ | bulk loading into triple stores, `grep`/`sort` |
| JSON-LD | `:jsonld` | `.jsonld` | ✓ | ✓ | web APIs, linked-data tools |
| RDF/XML | `:rdfxml` | `.rdf` `.owl` `.xml` | | ✓ | Protégé, older RDF tools |
| JSON | `:json` | `.json` | ✓ | ✓ | Python/JavaScript scripts, simple storage |
| CSV / TSV | `:csv` / `:tsv` | `.csv`, `.tsv` `.tab` `.txt` | ✓ | ✓ | spreadsheets, R/pandas, importing existing tables |
| SIF | `:sif` | `.sif` | ✓ | ✓ | Cytoscape, other interaction-network tools |
| GraphML | `:graphml` | `.graphml` | | ✓ | Cytoscape, Gephi, yEd, Graphs.jl |
| DOT | `:dot` | `.dot` `.gv` | | ✓ | Graphviz figures |

Every format also has its own functions, named `read_<format>`/`write_<format>` (the table
functions are `read_table`/`write_table`). Each takes either a file path or an `IO`, which is
handy for in-memory work, pipes or compressed streams:

```julia
ttl = sprint(write_turtle, kg)                # to a String
kg3 = read_turtle(IOBuffer(ttl))              # from a String
open("loop.nt", "w") do io
    write_ntriples(io, kg)
end
```

## What survives a round trip

| Format | Every field | Ids | Prefixes and base | Order |
|---|:-:|:-:|:-:|:-:|
| Turtle, N-Triples, JSON-LD | ✓ | ✓ | ✓ (Turtle and JSON-LD store them; N-Triples needs the same `base`/`prefixes` when reading) | ✓ |
| JSON | ✓ | ✓ | ✓ | ✓ |
| CSV / TSV | ✓ | ✓ | — (pass `prefixes` to `KnowledgeGraph` and `into`) | ✓ |
| SIF | only nodes, edges and relationship types | ✓ | — | — |
| RDF/XML, GraphML, DOT | write-only | | | |

"Every field" means that `load(save(kg))` gives back a graph whose resources compare equal field by field.

## RDF formats: Turtle, N-Triples, JSON-LD, RDF/XML

These write the graph as RDF triples in the BioNExt ontology's vocabulary. [RDF mapping](07-rdf.md)
describes exactly what is written. A short excerpt of the Turtle output:

```julia
print(first(sprint(write_turtle, kg), 480))
```

```
@prefix bn: <https://w3id.org/bionext/ontology/> .
@prefix bnr: <https://w3id.org/bionext/resource/> .
...
<https://identifiers.org/UniProt:P04637> a bn:Protein ;
    bn:name "p53" ;
    bn:synonyms "TP53", "LFS1" ;
    bn:organism <https://identifiers.org/NCBITaxon:9606> ;
    bn:cellularLocation bn:Nucleus ;
    bn:participatesInEdge bnr:e1, bnr:e2 .
```

**Writer option (all four formats)**

| Keyword | Default | Effect |
|---|---|---|
| `inverses` | `true` | Also write the inverse direction of properties stored one way (`bn:hasVariant`, `bn:participatesInPathway`, `bn:memberOfComplex`, `bn:participatesInEdge`, …). With `false` the output is smaller, but SPARQL queries without a reasoner see only one direction. |

```julia
length(triples(kg)), length(triples(kg; inverses = false))    # -> (41, 33)
```

**Reader options (Turtle, N-Triples, JSON-LD)**

| Keyword | Default | Effect |
|---|---|---|
| `base` | the file's `bnr:` prefix, else the BioNExt resource namespace | namespace whose IRIs become bare ids |
| `prefixes` | the prefixes declared in the file | extra prefixes used to shorten IRIs into CURIE ids |

On reading:

- Every subject typed with a concrete BioNExt class (`a bn:Protein`, …) becomes a resource.
- Every `bn:` predicate is mapped back to its field. Either direction of an inverse pair is
  accepted, so a file that only says `bnr:pw bn:pathwayComponent bnr:e1` and one that only says
  `bnr:e1 bn:participatesInPathway bnr:pw` give the same graph.
- Triples with other predicates (`rdfs:label`, `skos:*`, your own) are **ignored**.
- IRIs in the old namespace `https://jamiesilakom618.github.io/BioNExt/` are upgraded to the current `https://w3id.org/bionext/`.

**Turtle reader coverage**

The Turtle reader supports the full RDF 1.1 Turtle syntax:

- `@prefix`/`@base` and SPARQL-style `PREFIX`/`BASE`
- prefixed names, including escaped local names
- `a`, and `;`/`,` lists
- blank nodes (`_:x`, `[]`, `[ … ]`) and collections `( … )`
- short and long (`"""…"""`, `'''…'''`) strings with escapes, language tags and datatypes
- integers, decimals, doubles and booleans

It doesn't validate IRI characters or language tags strictly.

**JSON-LD reader coverage**

The JSON-LD reader handles compacted and expanded documents:

- an inline `@context`: prefix definitions, term definitions as a string or `{"@id": …, "@type": "@id"}`, and `@vocab`
- `@graph`, `@id` and `@type`
- value objects (`@value` with `@type`/`@language`), plus native numbers and booleans
- node references and nested node objects

It doesn't fetch remote `@context` URLs and doesn't implement framing, `@reverse` or `@list`.
For those documents, convert them with a full JSON-LD processor first.

**RDF/XML** is write-only. To read an `.owl` or `.rdf` file, convert it to Turtle with any RDF
tool, for example `riot --output=turtle file.owl > file.ttl` (Apache Jena) or
`rapper -o turtle file.rdf > file.ttl` (Raptor). Then `load` the result.

## Native JSON

A plain JSON document. It has nothing RDF-specific: one object per resource, with its
`class`, its `id`, and every non-empty field under its Julia name. This is the easiest format to
produce or consume from Python, JavaScript or R.

```julia
save("loop.json", kg)
print(read("loop.json", String)[1:330])
```

```json
{
  "format": "bionext-json",
  "version": 1,
  "base": "https://w3id.org/bionext/resource/",
  "prefixes": {},
  "resources": [
    {
      "class": "Taxon",
      "id": "NCBITaxon:9606",
      "name": "Homo sapiens"
    },
    ...
```

To create such a file from another language, write the same structure. The rules:

- `class` is the ontology class name (`"Complex"`, not `"MolecularComplex"`).
- Vector fields take an array, or a single value.
- Terms are strings (`"Nucleus"`).
- Dates are ISO strings (`"2026-10-01T00:00:00"`).
- Unknown fields cause a warning and are skipped.

Only `resources` is required.

```julia
write("from_python.json", """
{"resources": [
  {"class": "Protein", "id": "UniProt:P38398", "name": "BRCA1", "cellular_location": "Nucleus"},
  {"class": "Interaction", "id": "x1", "type": "Binding",
   "left": "UniProt:P38398", "right": ["UniProt:P04637"], "confidence": 0.7}
]}""")
py = load("from_python.json")
py["UniProt:P38398"].cellular_location     # -> [:Nucleus]
```

## Tables: CSV and TSV

### Exporting

`save("x.tsv", kg)` writes one row per resource. The first two columns are `class` and `id`,
followed by one column per field used by any exported type. Multi-valued cells are joined with `|`,
and cells that contain the delimiter, quotes or newlines are quoted the RFC 4180 way. The table
reads back losslessly.

Use `types` to export one kind of resource. For example, write a node table and an edge table
for spreadsheet work:

```julia
save("nodes.csv", kg; types = NodeEntity)
save("edges.csv", kg; types = EdgeEntity)
println(read("edges.csv", String))
```

```
class,id,name,synonyms,organism,db_xrefs,external_ids,provenance,publications,type,left,right,weight,confidence
Interaction,e1,,,,,,,,Binding,UniProt:Q00987,UniProt:P04637,,0.98
Influence,e2,,,,,,,,RegulateExpression,UniProt:P04637,HGNC:6973,,
Influence,e3,,,,,,,,Inhibition,UniProt:Q00987,e2,0.8,
```

**Writer options**

| Keyword | Default | Effect |
|---|---|---|
| `types` | `Resource` (everything) | export only resources of this type (abstract types allowed) |
| `delim` | `','` for `.csv`, `'\t'` for `.tsv` | column separator (for `write_table` on an `IO`, the default is tab) |
| `list_sep` | `"|"` | separator for multi-valued cells |

### Importing your own tables

`load` reads any delimited table. Every row becomes a resource, or updates one. Columns are
matched to fields **by name**, and `mapping` renames the columns that don't match.

**Reader options**

| Keyword | Default | Effect |
|---|---|---|
| `type` | — | the class for every row, when there is no `class` column (e.g. `type = Gene`) |
| `mapping` | `Dict()` | column name ⇒ field, e.g. `Dict("Gene symbol" => :name, "source" => :left)` |
| `list_sep` | `"|"` | separator for multi-valued cells |
| `delim` | from the extension | column separator |
| `into` | — | add rows to this graph instead of a new one (`load!` sets it for you) |

Rules:

- **Class:** a `class` column, when present and non-empty, overrides `type`.
- **Ids:** rows without an `id` (no such column, or an empty cell) get generated ids such as
  `influence-1` and `influence-2`, skipping any that are taken.
- **Updates:** a row whose id already exists **with the same class** updates that resource.
  Non-empty cells overwrite the field and empty cells leave it untouched.
- **Unknown columns** are ignored.
- **Conversion:** cells are converted to the field's type. A cell that doesn't convert (`"abc"` in
  `net_charge`) raises an error naming the row and column.

A gene list exported from a database:

```julia
write("hgnc.csv", """
hgnc_id,symbol,alias_symbol,location
HGNC:11998,TP53,p53|LFS1,17p13.1
HGNC:6973,MDM2,HDM2,12q15
HGNC:1784,CDKN1A,P21|CIP1,6p21.2
""")
genes = load("hgnc.csv"; type = Gene,
             mapping = Dict("hgnc_id" => :id, "symbol" => :name, "alias_symbol" => :synonyms))
genes["HGNC:1784"].synonyms          # -> ["P21", "CIP1"]
```

An edge list from a regulatory network, loaded into the same graph:

```julia
write("regulation.tsv", """
source\ttarget\teffect\tscore\tpmid
HGNC:11998\tHGNC:6973\tActivation\t0.9\tPMID:8319905
HGNC:11998\tHGNC:1784\tActivation\t0.95\tPMID:8242752
""")
load!(genes, "regulation.tsv"; type = Influence,
      mapping = Dict("source" => :left, "target" => :right, "effect" => :type,
                     "score" => :confidence, "pmid" => :publications))
[(e.id, e.type, e.confidence) for e in edges(genes)]
# -> [("influence-1", :Activation, 0.9), ("influence-2", :Activation, 0.95)]
```

The same column can't feed two fields. If you need that, load the file twice with
different mappings, or transform the table before loading.

## Network formats

BioNExt edges are richer than the arcs of an ordinary network. An edge can have several
participants on each side, and an `Influence` can point at another edge or a pathway. Network
formats therefore **flatten** edges, in one of two ways:

| Mode | Each BioNExt edge becomes | Loses |
|---|---|---|
| `reify = false` (default) | one arc for every (left, right) pair, labelled with its relationship type | n-ary grouping (a 2→2 reaction becomes 4 arcs) |
| `reify = true` | a node of its own, with `left → edge` and `edge → right` arcs | nothing |

```julia
net = network(kg)
[(a.source, a.type, a.target) for a in net.arcs]
# -> [("UniProt:Q00987", :Binding, "UniProt:P04637"),
#     ("UniProt:P04637", :RegulateExpression, "HGNC:6973"),
#     ("UniProt:Q00987", :Inhibition, "e2")]
length(network(kg; reify = true).arcs)            # -> 6
```

In the default mode, an edge that is the target of another edge (`e2` above) appears as a node
in its own right, so no arc is dropped. `network` returns `(nodes, arcs)`. Each `Arc` has
`source`, `target`, `type`, `edge` (the id of the BioNExt edge it comes from) and `role`
(`:pair`, `:left` or `:right`). Use it to feed any graph package directly.

### SIF

Writing gives one line per arc, `source<TAB>type<TAB>target`, followed by a line for each
isolated node. Reading accepts the usual SIF variants: tab- or space-separated, several targets
per line (`A pp B C D`), and single-node lines.

```julia
write("ppi.sif", """
TP53\tactivation\tMDM2\tCDKN1A
MDM2\tpp\tTP53
ATM\tphosphorylation\tTP53
""")
ppi = load("ppi.sif"; relationships = Dict("pp" => :Binding))
[(e.left[1], e.type, e.right[1]) for e in edges(ppi)][1:2]
# -> [("TP53", :Activation, "MDM2"), ("TP53", :Activation, "CDKN1A")]
```

**`read_sif` options**

| Keyword | Default | Effect |
|---|---|---|
| `node_type` | `Protein` | class of nodes created for unknown ids |
| `edge_type` | `Interaction` | class of the edges created |
| `relationships` | `Dict()` | SIF type ⇒ vocabulary term, e.g. `Dict("pp" => :Binding, "pd" => :Expression)` |
| `into` | — | add to an existing graph |

Relationship names are matched to vocabulary terms by id or by label, ignoring case, spaces,
`-` and `_`. So `activation`, `Activation` and `state-transition` all resolve. Names that match
nothing are kept as-is, and `validate` reports them so you can add a `relationships` entry.
Edges get ids `edge-1`, `edge-2`, …

`write_sif` accepts `reify`.

### GraphML

For Cytoscape (*File → Import → Network from File*), Gephi, yEd, or Graphs.jl through GraphIO.
Nodes carry the attributes `class` and `name`. Arcs carry `type`, `edge_id`, `class`, `role`,
`weight` and `confidence`, so you can style and filter by relationship type.

```julia
save("loop.graphml", kg)
save("loop-reified.graphml", kg; reify = true)
```

### DOT (Graphviz)

```julia
save("loop.dot", kg)
```

Render it with `dot -Tsvg loop.dot -o loop.svg`.

- Node shapes follow the class: genes and DNA are boxes, proteins ellipses, small molecules
  diamonds, complexes octagons, pathways tabs, and reified edges points.
- Arcs are labelled with the relationship type.
- Inhibition, repression and suppression arcs end in a tee (⊣).

## Choosing a format

- **To publish, or to exchange with other RDF users:** Turtle, or JSON-LD for web services.
- **To load into a triple store** (GraphDB, Virtuoso, Fuseki, Blazegraph): N-Triples.
- **To edit in a spreadsheet, or analyse in R or pandas:** TSV/CSV, with `types` to split nodes
  from edges.
- **For quick storage between Julia sessions, or as an interface to scripts in other languages:** JSON.
- **To visualise, or for network analysis:** GraphML, or SIF for older Cytoscape workflows. Use
  `reify = true` when the edges target other edges.
- **For a figure in a paper:** DOT.
